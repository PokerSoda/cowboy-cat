# 2026-10-09

## 工程结构分析（cowboy-cat，Cocos Creator 3.8x 推箱子类解谜游戏）

通读了全部 37 个 .ts 文件，结论：

- **架构分层**：levels/（TS 纯数据关卡配置）、enums/（统一枚举）、base/（Singleton、StateMachine/State/SubStateMachine、EntityManager）、runtime/（DataManager/EventManager/ResourceManager/FadeManager 四个单例）、scripts/（player/enemy/tile/portal/scene 游戏逻辑）、ui/（Controller/Shake/Draw）。
- **单例**：有。base/Singleton.ts 泛型基类 `GetInstance<T>()`，四个 Manager 通过 `static get Instance()` 继承使用。
- **事件系统**：有。EventManager（on/off/emit + ctx），事件名集中在 enums/EVENT_ENUM。玩家攻击/浮台/传送/撤销均走事件，实体间互不持引用。
- **状态机**：有。三层结构 StateMachine（params + run + resetTrigger）→ SubStateMachine（方向子状态）→ State（loadDir 加帧图、运行时用 ObjectTrack 拼 AnimationClip）。注意：FSM 主要驱动**动画表现**，谜题逻辑（碰撞/攻击/传送判定）在 PlayerManager 的 willBlock/willAttack 等方法里，不是状态机。
- **关卡配置**：level1-3.ts 导出 ILevel（mapInfo 二维数组 {src, type} + player/enemy/portals/door/switchs），levels/index.ts 汇总 Record。加新关卡 = 新建 levelN.ts + 注册。
- **localStorage 存档**：❌ 没有。records 撤销记录只在内存（DataManager.records），levelIndex 每次 onLoad 重置为 1。
- **资源管理**：ResourceManager 封装 resources.loadDir（Promise 化），但 ❌ 没有任何 release/releaseAll 调用；切关时 destroyAllChildren 只删节点不释放资源缓存。

## 已知代码隐患（后续可修）
- EventManager.off 对未注册事件名会直接抛错（`get(eventName).findIndex` 无空值保护）。
- PlayerManager.willMoveFloat 返回 '' 但调用处判 `!== null`，且 off 时若 null 会崩。
- willBlock 中 `tileInfo[x-1][y]` 在 x=0 时会越界抛异常。
- BattleManager.nextLevel 超过 level3 后无兜底（关卡不存在时静默卡死）。
- State.init 里 filteredFrames 为空时 `frames.length` 会 NaN duration。
- Singleton._instance 类型为 any，静态继承下多个子类单例可共用基类静态槽位（当前恰好各自赋 own property 才没出问题）。
